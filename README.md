# GMES HDPS 5S 활동관리 Prototype (v4 — 실제 생산현장팀 반영)

`index.html` / `styles.css` / `app.js` 3개 파일로 동작하는 단일 정적 프로토타입입니다. `ARCHITECTURE.md`는 업무 로직 문서로 기존대로 유지합니다.

## v4 — 실제 생산현장팀 16개 반영
`울산캠퍼스_26년_2분기_소그룹활동_과제_평가(배포용).xlsx`에 등장하는 **생산현장팀 16개 전체**로 조직마스터(TEAMS)를 교체했습니다. 이전까지는 조립1팀 등 가상의 예시 팀 5개였습니다.

**반영한 16개 팀** (8개 부서로 그룹화)
- 대형조립부: 대형Att.팀·대형메인팀·대형상부팀
- 프레임제작부: 프레임제작팀 / Boom제작부: Boom제작팀
- 중형조립부: 중형상부1팀·중형상부2팀·중형하부팀·중형Att팀·중형메인팀
- 휠로더조립부: 휠로더Front팀·휠로더리어팀·휠로더메인팀
- 초대형조립부: 초대형조립팀 / 성능시험부: 성능팀 / 트러블슈팅부: 트러블슈팅팀

**실데이터를 반영한 부분**
- 팀별 Audit 점수는 xlsx의 "평가결과"(S/A/B/C, 여러 건이면 평균)를 S=97/A=92/B=85/C=76로 환산해 그대로 사용했습니다. 예: Boom제작팀·휠로더리어팀은 S등급 과제 보유로 97.0점(정상), 대형Att.팀·대형메인팀·트러블슈팅팀은 C등급만 있어 76.0점(주의)으로 반영됩니다.
- 인원(headcount)은 원본 파일에 없어 부여한 **가정치**입니다 — 실제 인사마스터 연동 시 교체가 필요합니다.
- 팀별 월별 개선건수(MONTHLY)·Audit 이력(AUDIT_MONTHLY)·반복지적 파라미터는 하드코딩 대신 팀 규모·Audit 점수에 연동한 **규칙 기반 생성 함수**로 만들어, 팀이 몇 개든 자동으로 확장됩니다.
- 조회기간을 실제 xlsx 시점에 맞춰 2026년 1월~6월로 조정했습니다(이전 버전은 2025년 10월~2026년 3월).

**16개 팀 확장에 따른 화면 조정**
- 안돈보드가 자동 줄바꿈 그리드로 16개 팀을 모두 표시합니다.
- "월별·부서별 표준화 개선건수 / Audit 평가현황" 추이차트는 16개 팀 개별 선 대신 **8개 부서 단위로 집계**해서 표시합니다(16개 선은 가독성이 떨어져 그룹화했습니다). "팀별 5S 유형별 활동 현황"·반복지적 TOP5·개선요청 목록 등 나머지는 16개 팀 그대로 표시됩니다.
- HDPS34의 "개선요청" 목업 데이터도 16개 팀 각 1건씩으로 재배치했습니다. 다만 이 목업 지적사항/개선내용은 예시 데이터이며, xlsx의 실제 소그룹활동 과제 내용을 옮긴 것은 아닙니다(xlsx는 팀 목록·Audit 점수 산정에만 사용했습니다).

## 반복지적률 — "2개월 이상 연속 지적" 기준 (v3.2)
- `app.js`의 `computeRepeatStats()`가 팀×유형별 지적 발생 시계열을 만들고, 당월 지적 건 중 **전월에도 같은 팀×유형이 지적되었던 건**만 "반복"으로 집계합니다. 하드코딩된 숫자가 아니라 매번 이 규칙으로 다시 계산됩니다.
- 최초 월은 비교할 전월 데이터가 없어 반복지적률 산정에서 제외되며, 추이차트·TOP5 모두 **최근 5개월** 기준으로 표시됩니다.
- 지적 발생확률·반복(지속)확률을 팀 Audit 점수에 연동해뒀기 때문에, TOP5 순위가 Audit 등급이 낮은 팀일수록 자연스럽게 위로 오는 경향을 보입니다(다만 확률적 모델이라 매 팀 완벽히 등급순은 아닙니다).

## 아직 확인이 필요한 부분
- 공장 선택(`scopeSite`, CE01/CE02)은 현재 UI만 있고 실제 데이터 전환은 목업 상태입니다(현재 데이터는 전부 [CE01] 울산공장 기준).
- 16개 팀의 headcount(인원)는 가정치이므로 실제 HR 마스터 연동 시 교체가 필요합니다.
- HDPS34 목업 개선요청 14→16건은 예시 데이터이며 xlsx의 실제 과제 내용을 담고 있지 않습니다.

## 신규 확장 화면 — 5S 고도화 활동사례 현황
좌측 5번째 탭(★)으로 추가했습니다. 원 화면설계 요청서에는 없던 화면이라 "신규 확장 화면"으로 표기해뒀습니다.

- **"5S 고도화 사례" 정의**: 개선요청(HDPS34)에서 표준화(수평전개) 체크가 켜져 있고, 상태가 조치완료 이상(조치완료/5S모듈검증/Close)으로 확정된 건. Draft·요청등록·조치중 상태는 아직 "확보"로 세지 않습니다.
- **당월/누적 KPI 4종**: 당월 확보 건수, 누적 확보 건수(01월~기준월), 당월 확보팀 비율, 누적 확보팀 비율(전체 16개 팀 대비).
- **월별 사례 확보 추이**: 막대=당월 신규 확보 건수, 막대 아래 라벨=해당월까지 누적 건수.
- **작업장·팀별 확보 현황 표**: 16개 팀 전원에 대해 당월 확보 여부(뱃지)·누적 확보건수·최근 사례명·최근 확보일을 보여줍니다. 작업장(부서) 필터로 좁혀볼 수 있습니다.
- **확보된 사례 목록**: 실제 확정된 사례를 표로 나열합니다.
- 기준월 선택(상단 필터)에 따라 KPI·추이차트·팀별 표가 모두 "그 시점까지의 누적" 기준으로 다시 계산됩니다 — 예를 들어 2026년 3월을 선택하면 그 시점엔 아직 확보된 사례가 없어 전부 0으로 표시됩니다(4월부터 첫 사례 발생).

## 대시보드 구조 개편 (v4.1)
"세부 탭이 대시보드를 포함해서 맥락도 안 맞고 허접해 보인다"는 피드백을 반영했습니다. 근본 원인은 기능을 반복 요청 처리하며 하나씩 얹기만 하고 전체 구조를 다시 잡지 않았던 것이었습니다.

- **HDPS42 대시보드를 3단계 스토리 구조로 재편**: ① 활동 수준(안돈보드+KPI) → ② 현장 진단(부서별 추이·팀별 유형현황·문제점·반복지적) → ③ 개선 실행(Raw Data·등록현황·상세내역). 이전에는 11개 패널이 위계 없이 그냥 세로로 쌓여 있었습니다.
- **부서별 추이차트를 8개 선이 겹치는 결합차트(막대+선)에서 부서별 스파크라인 8행으로 교체**했습니다. 선이 서로 겹쳐 알아보기 어려웠던 문제를 해결했습니다.
- **"5S 부서별 등록현황"과 "5S 상세내역"을 별도 패널 2개에서 탭 전환되는 패널 1개로 통합**해 패널 개수를 줄였습니다.

## 5S 유형별 최취약 작업장 (v4.2)
"② 현장 진단" 섹션에 안돈보드 스타일 카드 6개(정리·정돈·청소·시각화관리·습관화·자주보전 각 1개)를 추가했습니다. 유형마다 당월 점수가 가장 낮은 팀을 자동으로 찾아 팀명·소속부서·점수를 표시합니다. HDPS33 감사점수 산식(`auditCategoryScore`)을 그대로 재사용해 팀별 Audit 실적 화면과 숫자가 일치합니다. 기준월을 바꾸면(상단 "당월" 선택) 이 패널도 함께 재계산됩니다.
